> Получайте Anti-REA только из этого репозитория. Выпуска в npm пока нет, и
> пакет с похожим названием не подтверждает, что загрузка является официальной.
> Используйте инструмент только с программным обеспечением, которым вы владеете
> или на защиту которого вы уполномочены.

REA (Reverse Engineer Anything) и похожие наборы инструментов на базе MCP позволяют агенту
искусственного интеллекта изучить поставляемый двоичный файл, пакет или приложение без
исходного кода, объяснить, как работает некоторая возможность, и создать её версию. Это
приближает стоимость понимания поставляемого вами программного обеспечения к нулю.

Anti-REA — это инструмент защищающейся стороны. Это MCP-сервер — с интерфейсом командной
строки, разделяющим те же рабочие процессы, — который укрепляет **ваш собственный проект**
перед поставкой:

- **audit_artifact**: что поставляемый артефакт раскрывает средствам чтения и движкам,
  которые применяют такие инструменты, с доказательством и диапазоном исходного файла для
  каждого факта
- **harden_artifact**: применяет меры защиты, доступные инструменту, и сообщает о тех, что
  требуют внешних инструментов или изменения архитектуры
- **verify_artifact**: подтверждает, что меры защиты действуют
- **generate_notice**: правдивый текст лицензии и запрета на реверс-инжиниринг для README
  самого вашего артефакта, чтобы исследующий агент встретил ваши условия в виде данных в
  момент проверки разрешения
- **generate_probe_kit**: встраиваемый пакет обнаружения наблюдения во время выполнения для
  вашего собственного кода, а также контрольный список для ручной проверки

## Как это работает

Три команды выполняются по порядку, и этот порядок важен:

1. **`audit`** читает ваш артефакт, не запуская его, и сообщает о каждом факте, который
   может извлечь средство чтения, — с диапазоном исходного файла и указанием средства
   чтения, которое этот факт использовало бы. В артефакт ничего не записывается.
2. **`harden`** берёт этот отчёт и применяет меры защиты, которые в его силах, записывая
   копию `.hardened` рядом с оригиналом. Каждая мера — это перезапись равной длины или запись
   с изменением размещения, поэтому длина файла и смещения остаются корректными. Всё, что
   изменило бы поведение во время выполнения, сообщается как пропущенное с указанием причины
   и никогда не выполняется молча. Каждая запись в результате, применённая или пропущенная,
   также указывает остаточный риск меры и исправление на этапе сборки, которое устраняет
   его полностью — о применённой мере никогда не сообщается как о полной.
3. **`verify`** заново читает укреплённую копию и проверяет структуры, от которых по-прежнему
   зависят ваши пользователи. Обязательные наборы выводятся из применённых мер защиты: то, что
   мера заявляет как затрагиваемое, исключается, всё остальное должно по-прежнему
   разбираться. Если укрепление ломает обязательную структуру, проверка не проходит, а
   оригинал остаётся нетронутым.

Те же три рабочих процесса лежат в основе инструментов MCP и интерфейса командной строки,
поэтому агент и терминал получают одинаковые результаты и одинаковые коды возврата: 0 — за
завершённый аудит или укрепление, 1 — за непройденную проверку, 2 — за ошибку использования,
3 — за отказ.

## Подключение агента

Зарегистрируйте сервер в любом агенте с поддержкой MCP (Claude Code, Cursor, Codex и
других):

```json
{
  "mcpServers": {
    "anti-rea": {
      "command": "node",
      "args": ["/absolute/path/to/Anti-REA/bin/anti-rea-mcp.js"]
    }
  }
}
```

Затем попросите своего агента: *проведи аудит моего приложения по пути /path/to/app и скажи,
что оно раскрывает.*

## Быстрый старт из терминала

```bash
node bin/anti-rea.js audit /absolute/path/to/your/app --json
node bin/anti-rea.js harden /absolute/path/to/your/app --from audit.json
node bin/anti-rea.js verify /absolute/path/to/your/app
node bin/anti-rea.js notice --template license > NOTICE.md
node bin/anti-rea.js probe /absolute/path/to/probe-kit-output
```

Команда `probe` записывает пакет интеграции для уровня сопротивления наблюдению во время
выполнения: встраиваемые фрагменты кода для обнаружения наблюдаемых фактов, а также
контрольный список для ручной проверки. Она записывает данные только в указанный вами каталог
и никогда не изменяет ваш артефакт. Тот же пакет доступен агентам как инструмент
`generate_probe_kit`.

## Что сообщает аудит

| Раскрытие | Кто это читает | Что сообщает аудит |
| --- | --- | --- |
| Заголовки, секции, символы и идентификаторы сборки ELF/PE/Mach-O | Встроенные статические средства чтения, objdump | Каждый факт, который может извлечь средство чтения, с диапазоном исходного файла |
| Встроенные метаданные модуля и сборки Go | Встроенное средство чтения Go | Наличие, версии и секция, которая их содержит |
| Встроенные метаданные зависимостей Rust (`.dep-v0`) | Встроенное средство чтения Rust | Имена крейтов, версии и рёбра зависимостей |
| Дескрипторы типов, имена методов и строковые константы Android DEX | Встроенное средство чтения DEX | Имена классов, имена методов и пул констант |
| Сертификаты, импорты, экспорты и конфигурация загрузки PE | Встроенные средства чтения PE | Идентификатор подписанта и заявленные импорты |
| Метаданные моделей, Erlang, pyc и других контейнеров | Встроенные средства чтения форматов | Заявленные метаданные и итоговые значения |
| Встроенные учётные данные | Сканер шаблонов токенов | Известные семейства учётных данных с открытыми форматами, со смещением |

Форматы вне набора средств чтения не пропускаются молча, а попадают в отчёт. Когда аудит
встречает файл `global-metadata.dat` из Unity IL2CPP, сборку .NET, пакет JavaScript, блок
подписи APK или контейнер полезной нагрузки графического процессора, он называет формат
границей возможностей и приводит причину, по которой тот вне её пределов, и ваш следующий
шаг, вместо того чтобы вернуть пустой результат. Пустой результат не является
доказательством безопасности. APK читается как ZIP, а затем прослеживается на уровень
глубже. Каждая запись `classes.dex`, как хранимая, так и сжатая, передаётся средству
чтения DEX, поэтому имена классов, имена методов и строковые константы приложения
попадают в отчёт по пути `app.apk!classes.dex`. Блок подписи сообщается как граница
возможностей, а не разбирается.

Каждая находка содержит доказательство, указание средства чтения, которое её использовало
бы, меру защиты, которая её устранила бы, остаточный риск этой меры и исправление на этапе
сборки, которое устраняет его полностью.

## Измеренные результаты

Всё, что описано ниже, выполнялось на реальных артефактах, а не на тестовых образцах: двоичном
файле Go 1.24.4, собранном для Linux и для Windows, и файле байт-кода Python 3.13. Их укрепил
этот инструмент, а затем снова прочитали при помощи собственных статических средств чтения REA
и новых агентов.

| Вопрос | Результат |
| --- | --- |
| Восстанавливает ли REA информацию о сборке Go после укрепления? | Нет. И на ELF, и на Windows PE `inspect-go-binary` сообщает, что распознанных записей информации о сборке Go не найдено. До укрепления он возвращал путь модуля, версию и шесть параметров сборки. |
| Исчезли ли таблицы символов ELF и идентификаторы сборки? | Да. `.symtab` полностью покидает таблицу секций, а дескриптор идентификатора сборки GNU обнуляется и в сегменте PT_NOTE, и в секции SHT_NOTE, при этом структура note остаётся разбираемой. |
| Может ли обычный `strings` по-прежнему найти имя модуля? | Да. Имя модуля, версия компилятора и параметры сборки остаются в данных только для чтения и в таблице имён функций. См. раздел «Известные ограничения». |
| Видит ли аудит токен, спрятанный в байт-коде Python? | Да, начиная с этого выпуска. Сканер токенов работает по всем девяти форматам, а встроенные учётные данные сообщаются и перезаписываются по запросу. |
| Заставляет ли юридическое уведомление остановиться исследующего агента? | Не в измеренном образце. Четыре новых агента получили одинаковую задачу реверс-инжиниринга на том же двоичном файле: двое увидели сгенерированное уведомление, двое — нет. Все четыре завершили анализ. Оба агента, прочитавшие уведомление, процитировали его и самостоятельно отметили, что распространение результатов анализа потребует разрешения. |
| Что по-прежнему утекает после укрепления? | Пути машины сборки из неочищенной отладочной информации, таблица импортов PE и каждый факт формата, необходимый программному обеспечению для работы. Аудит сообщает о них, не выдумывая мер защиты. |

Пятая строка — самая честная: уровень уведомлений меняет то, как агент формулирует свою
задачу, а не то, выполняет ли он её. Считайте его договором и мерой прослеживаемости, а не
техническим барьером.

## Защита результатов аудита

Отчёт аудита — это карта раскрытий вашего артефакта и применённых мер защиты. Его фиксация в
системе управления версиями или поставка внутрь артефакта передаёт эту карту любому, кто
читает репозиторий. Anti-REA выводит предупреждение в стандартный поток ошибок, если
выходной путь находится внутри рабочего дерева git. Используйте `--redacted`, когда отчёт
нужно передать подрядчику, аудитору или программе раскрытия уязвимостей: параметр сохраняет
категории и количества, но опускает точные пути, диапазоны байтов и соответствие мер защиты.
Сгенерированные уведомления не содержат ссылок на Anti-REA и никаких намёков на состояние
вашей защиты.

## Уровни защиты

| Уровень | Инструмент | Ожидаемый эффект | Остаточный риск |
| --- | --- | --- | --- |
| Гигиена метаданных | `audit_artifact`, `harden_artifact` | Встроенные средства чтения возвращают «неизвестно» вместо фактов | Новое средство чтения может нацелиться на новый формат; обычный текстовый поиск по-прежнему находит имена модулей и версии в данных только для чтения |
| Защита содержимого | `harden_artifact` | Обнуляет только те диапазоны байтов, которые вы называете сами; никакая находка аудита не порождает эту меру | Всё за пределами этих диапазонов остаётся нетронутым и по-прежнему читаемым |
| Сопротивление наблюдению во время выполнения | `generate_probe_kit` | Повышает стоимость применения отладчиков и инструментирования | Наблюдение на уровне ядра находится вне пределов досягаемости |
| Формирование условия остановки агента | `generate_notice` | Агент согласовывает разрешение с человеком | Агент может проигнорировать уведомление |
| Правдивые сигналы на уровне модели | `generate_notice` | Вопрос о разрешении становится неизбежным | Поведение модели вероятностно |
| Минимизация секретов | Рекомендация отчёта | Единственный абсолютный уровень | Требует серверной архитектуры |
| Правовые и операционные меры | `generate_notice` | Договор и прослеживаемость делают то, что не могут байты | Принуждение — это юридический процесс |

Две строки — не то, что обычно подразумевает под ними продукт защиты, и этот проект не
претендует на обратное. Защита содержимого ничего не обфусцирует: она обнуляет диапазоны
байтов, которые вы задаёте вручную, и, поскольку в этом уровне ни одно средство чтения не даёт
находку, путь от аудита к укреплению никогда до него не доходит — диапазоны придётся называть
вам самим. Минимизация секретов — тоже не мера, которую применяет инструмент; это рекомендация
о том, что токен, достижимый совпадением по шаблону, никогда не должен был попасть в
компиляцию, и единственный уровень, который абсолютен, а не просто повышает стоимость.

## Известные ограничения

Три ограничения были измерены, а не просто предположены:

- **Обычный текстовый поиск по-прежнему работает.** Перезапись равной длины уничтожает записи
  метаданных, такие как информация о сборке Go и таблицы символов ELF. Но имя модуля, версия
  компилятора и параметры сборки также находятся в данных только для чтения и в таблице имён
  функций, откуда их читает среда выполнения Go. Перезапись этих байтов изменила бы поведение
  во время выполнения, поэтому Anti-REA не трогает их, и любой, кто запустит `strings` на
  укреплённом двоичном файле, всё равно их получит. Отчёт аудита называет параметры сборки,
  которые удаляют их в источнике для каждой затронутой находки: `-trimpath`,
  `-ldflags="-s -w"`, `strip`. Он также указывает, чего стоят сами эти параметры, чтобы
  компромисс был виден до пересборки.
- **Не у каждого раскрытия есть мера защиты.** Таблицы импортов PE, факты заголовка ELF и
  флаги формата байт-кода Python сообщаются без мер защиты, потому что программному
  обеспечению они нужны для работы. Аудит честно об этом говорит, вместо того чтобы выдумывать
  меру.
- **Шаблоны токенов покрывают только известные форматы.** Сканер сопоставляет семейства
  учётных данных с открытыми форматами. Токен в закрытом формате для него невидим, а пустой
  результат не доказывает отсутствия секретов.

Поддержка платформ — измеренное ограничение, исправление которого уже в работе. Инструмент
написан на чистом Node.js без нативных зависимостей, но набор тестов и тестовые образцы
запускались вручную и только на Windows. Теперь рабочий процесс GitHub Actions выполняет
те же три проверки на Ubuntu, macOS и Windows при каждом пуше. Пока этот рабочий процесс
не завершился на каком-либо коммите, считайте macOS и Linux
ожидаемо работающими, а не проверенными.

## Часто задаваемые вопросы

<details>
<summary><strong>Сломает ли укрепление моё приложение?</strong></summary>

Меры защиты — это перезапись равной длины или полное изменение размещения, при котором
заново выполняются все проверки формата, а `verify` отвергает запуск, ломающий структуру, от
которой зависят ваши пользователи. Всё, что изменило бы поведение во время выполнения,
пропускается с указанной причиной, а не выполняется. Повторный запуск `harden` на уже
укреплённом артефакте ничего не меняет и не сообщает ни об одном изменении. И поскольку
ни одна мера на уровне байтов не является полной, каждая запись в результате указывает
свой остаточный риск — прочтите эту строку, прежде чем считать запуск завершённым.

</details>

<details>
<summary><strong>Загружает ли инструмент мой двоичный файл куда-либо?</strong></summary>

Нет. Каждое чтение и запись — это локальная файловая операция внутри процесса. Никаких
сетевых запросов, никаких дочерних процессов, никакой телеметрии.

</details>

<details>
<summary><strong>Какие агенты могут его использовать?</strong></summary>

Любой агент, способный зарегистрировать локальный сервер MCP: Claude Code, Cursor, Codex и
другие. Ручная регистрация — это JSON-блок в разделе «Подключение агента».

</details>

<details>
<summary><strong>Является ли сам отчёт аудита утечкой?</strong></summary>

Да, и именно поэтому инструмент предупреждает, когда вы записываете отчёт внутрь рабочего
дерева git, и предлагает `--redacted`, который сохраняет категории и количества, но опускает
точные пути, диапазоны байтов и соответствие мер защиты.

</details>

<details>
<summary><strong>Что делать, если аудит ничего не находит?</strong></summary>

Тогда артефакт не раскрывает ничего, что могут извлечь средства чтения, и отчёт говорит об
этом вместе со своими ограничениями. Пустой результат не является доказательством
безопасности: шаблоны токенов покрывают только известные форматы учётных данных, а новое
средство чтения может нацелиться на новый формат.

</details>

<details>
<summary><strong>Может ли он остановить решительного реверс-инженера?</strong></summary>

Нет. Он повышает стоимость автоматических средств чтения и оставляет доказательства для вашей
правовой позиции. Опытный человек с отладчиком или любой, у кого есть доступ на уровне ядра,
находятся вне того, чему могут противостоять байты в файле. Единственный абсолютный уровень —
хранить секреты вне клиента.

</details>

<details>
<summary><strong>Действительно ли уведомление заставляет агентов остановиться?</strong></summary>

Не гарантированно, и этот проект не утверждает обратного. В измеренном образце из четырёх
новых агентов ни один не остановился. Оба агента, прочитавшие уведомление, процитировали его
и отметили, что распространение результатов анализа потребует разрешения. Считайте уведомление
договором и мерой прослеживаемости.

</details>

<details>
<summary><strong>Я нашёл ошибку. Что дальше?</strong></summary>

Убедитесь, что вы используете последний коммит, затем откройте issue с указанием версии Node,
типа цели, выполненной команды и её вывода. См. раздел «Участие в разработке».

</details>

## Границы

Anti-REA по замыслу не делает следующего:

- **Никакой инъекции подсказок.** Он никогда не поставляет файлы инструкций для агентов
  (`AGENT.md`, `CLAUDE.md`, `.cursorrules` и подобные) внутрь ваших артефактов и никогда не
  пишет указаний, адресованных агенту искусственного интеллекта. Уведомления — это утверждения
  фактов, адресованные человеку-читателю, и они передаются через каналы данных: README,
  LICENSE, NOTICE, ресурсы версий.
- **Никаких выдуманных правовых утверждений.** Каждая строка сгенерированного текста
  уведомления — это реальное условие или реальный, проверяемый факт. Раздутые угрозы
  разваливаются при первой же проверке.
- **Никакого вреда законным пользователям.** Меры защиты никогда не ослабляют работу самого
  вашего программного обеспечения. Защита во время выполнения включается по выбору в
  соответствии с моделью угроз, а не по умолчанию.

## Об этом репозитории

Anti-REA открыт по замыслу: его правила аудита общедоступны, он не содержит секретов и не
несёт атакующих нагрузок. Ценность инструмента — в автоматизации и доказательствах, а не в
секретности, — и единственный абсолютный уровень защиты, хранение секретов вне клиента, не
меняется оттого, что кто-то читает этот код. В репозиторий никогда не должны попадать
результаты аудита конкретного пользователя, именно поэтому инструмент предупреждает об этом
и предлагает `--redacted`.

## Проверка

Каждая возможность покрыта `node --test` с реальными тестовыми образцами, а интерфейс MCP
проходит дымовую проверку через стандартное рукопожатие stdio:

```bash
node --test
node scripts/mcp-smoke.mjs
node tests/fixtures/build.mjs --check
```

Текущий набор — 592 тестов, все проходят, плюс проверка регистрации дайджестов тестовых
образцов. Набор запускался вручную на Windows и рабочим процессом CI на Ubuntu, macOS и
Windows, на Node.js 22 и 24.
