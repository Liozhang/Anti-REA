> [!IMPORTANT]
> Anti-REA は、このリポジトリからのみ取得してください。npm での公開はまだなく、
> 名前の似たパッケージであっても、そのダウンロード元が公式であることは示しません。
> あなたが所有する、または保護を許可されたソフトウェアにのみ使用してください。

REA（Reverse Engineer Anything）や同様の MCP ベースのツールチェーンがあれば、AI エージェントは
ソースコードを見ずに出荷済みのバイナリ、パッケージ、アプリケーションを調査し、機能の仕組みを
説明し、同じものを構築できます。これによって、あなたが出荷するソフトウェアを理解するための
コストは、ほぼゼロに近づきます。

Anti-REA は、防御する側のための対になるツールです。同じワークフローを共有するコマンドライン
インターフェースを備えた MCP サーバーであり、**あなた自身のプロジェクト**が出荷される前に
それを強化します：

- **audit_artifact**：出荷したアーティファクトが、そうしたツールが使うリーダーやエンジンに
  何を露出しているかを、各事実の証拠となるソース内の範囲とともに示します
- **harden_artifact**：本ツールが実行できる緩和策を適用し、外部ツールやアーキテクチャの
  変更が必要なものは報告します
- **verify_artifact**：緩和策が実際に効いていることを確認します
- **generate_notice**：アーティファクト自身の README に貼る、事実に基づくライセンス表記と
  リバースエンジニアリング禁止の文言を生成します。調査中のエージェントが許可を確認する
  瞬間に、あなたの条件をデータとして目にするようになります
- **generate_probe_kit**：あなたのコードに埋め込める、実行時の観測を検知するパッケージと、
  手動のチェックリストを生成します

## 仕組み

3 つのコマンドを順番に実行します。この順序には意味があります：

1. **`audit`** は、アーティファクトを実行せずに読み取り、リーダーが抽出しうるすべての
   事実を、証拠となるソース内の範囲と、それを使うであろうリーダーとともに報告します。
   アーティファクトへの書き込みは一切行いません。
2. **`harden`** はその報告を受け取り、適用できる緩和策を適用し、オリジナルの隣に
   `.hardened` コピーを書き出します。すべての緩和策は等長の上書きか再配置の書き込みで
   行われるため、ファイル長とオフセットは有効なまま保たれます。実行時の動作を変えて
   しまうものは、理由を付けてスキップされたものとして報告され、黙って試みられることは
   ありません。
3. **`verify`** は強化後のコピーを読み直し、ユーザーが依然として依存している構造を
   検査します。必須となる構造の集合は、適用された緩和策から導出されます。緩和策が触れると
   宣言したものは免除され、それ以外はすべて解析できなければなりません。必須構造を壊す
   強化の実行は審査で不合格となり、オリジナルには手が加えられません。

同じ 3 つのワークフローが MCP ツールと CLI を支えているため、エージェントから実行しても
ターミナルから実行しても、結果と終了コードは同じです。監査または強化の正常完了は 0、
検証の失敗は 1、使用法エラーは 2、拒否は 3 です。

## エージェントへの登録

MCP に対応する任意のエージェント（Claude Code、Cursor、Codex など）に本サーバーを
登録してください：

```json
{
  "mcpServers": {
    "anti-rea": {
      "command": "node",
      "args": ["/absolute/path/to/Anti-REA/bin/anti-rea-mcp.js"]
    }
  }
}
```

次に、エージェントにこう依頼します：*/path/to/app にあるアプリを監査して、何が漏えいしているか教えて。*

## ターミナルからのクイックスタート

```bash
node bin/anti-rea.js audit /absolute/path/to/your/app --json
node bin/anti-rea.js harden /absolute/path/to/your/app --from audit.json
node bin/anti-rea.js verify /absolute/path/to/your/app
node bin/anti-rea.js notice --template license > NOTICE.md
node bin/anti-rea.js probe /absolute/path/to/probe-kit-output
```

`probe` コマンドは、実行時の観測への耐性層のための統合パッケージを書き出します。
観測可能な事実を検知する、埋め込み可能なスニペットと、手動のチェックリストです。
書き込み先はあなたが指定したディレクトリだけで、あなたのアーティファクトを変更する
ことはありません。エージェント側では、同じパッケージを `generate_probe_kit` ツールと
して利用できます。

## 監査が報告する内容

| 露出する情報 | 誰が読み取るか | 監査が報告する内容 |
| --- | --- | --- |
| ELF/PE/Mach-O のヘッダー、セクション、シンボル、ビルド ID | 内蔵の静的リーダー、objdump | リーダーが抽出できるすべての事実（ソース内の範囲付き） |
| 埋め込まれた Go モジュールとビルドのメタデータ | 内蔵の Go リーダー | その存在、バージョン、およびそれを保持するセクション |
| 埋め込まれた Rust の依存メタデータ（`.dep-v0`） | 内蔵の Rust リーダー | クレート名、バージョン、依存関係のエッジ |
| Unity IL2CPP のメタデータ | 内蔵の IL2CPP リーダー | 復元可能な型名とメソッド名 |
| .NET のメタデータと CIL | 内蔵のマネージドコード用リーダー | アセンブリの事実とメンバーの一覧 |
| JavaScript のソースマップとモジュールグラフ | 内蔵の JavaScript リーダー | 復元可能な元のソースコード |
| PE の証明書、インポート、エクスポート、読み込み設定 | 内蔵の PE リーダー | 署名者の識別情報と宣言されたインポート |
| モデル、SQLite、Erlang、pyc などのコンテナのメタデータ | 内蔵のフォーマットリーダー | 宣言されているメタデータと総数 |
| 埋め込まれた資格情報（クレデンシャル） | トークンパターンのスキャナー | 公開フォーマットを持つ既知の資格情報のカテゴリー（オフセット付き） |

各検出結果には、その証拠、それを使うであろうリーダー、そしてそれを取り除く緩和策が
付随します。

## 実測結果

以下はすべて、実際のアーティファクト（テスト用のフィクスチャではありません）を使って
実施しました。Linux 向けと Windows 向けにビルドした Go 1.24.4 のバイナリと、
Python 3.13 のバイトコードファイルを本ツールで強化し、その後 REA 自身の静的リーダーと
新規に起動したエージェントで読み返しました。

| 質問 | 結果 |
| --- | --- |
| 強化後に REA は Go のビルド情報を復元できますか？ | できません。ELF と Windows PE のどちらでも、`inspect-go-binary` は認識できる Go のビルド情報レコードが見つからなかったと報告します。強化前は、モジュールパス、バージョン、6 つのビルド設定が返っていました。 |
| ELF のシンボルテーブルとビルド ID は消えましたか？ | はい。`.symtab` はセクションテーブルから完全になくなり、GNU のビルド ID ディスクリプタは PT_NOTE セグメントと SHT_NOTE セクションの両方でゼロクリアされます。note 構造自体は解析可能なまま保たれます。 |
| 素の `strings` コマンドでもモジュール名は見つかりますか？ | はい。モジュール名、コンパイラーのバージョン、ビルド設定は、読み取り専用データと関数名テーブルに残っています。「既知の制限」を参照してください。 |
| Python バイトコードに埋め込まれたトークンを監査で見つけられますか？ | はい、このリリースから可能です。トークンのスキャナーは 8 つのフォーマットすべてを対象に動作し、埋め込まれた資格情報は報告され、要求に応じて上書きされます。 |
| 法的な通知があれば、調査中のエージェントは手を止めますか？ | 実測したサンプルでは止まりませんでした。新規に起動した 4 つのエージェントに、同じバイナリに対する同じリバースエンジニアリングの課題を与え、2 つには生成された通知を読み取らせ、2 つには読み取らせませんでした。4 つすべてが分析を完了しました。通知を読んだ 2 つのエージェントはどちらも通知を引用し、分析結果を再配布するには許可が必要だと自ら指摘しました。 |
| 強化後も何が漏えいしますか？ | strip されていないデバッグ情報に含まれるビルドマシンのパス、PE のインポートテーブル、そしてソフトウェアの実行に必要なあらゆるフォーマットの事実です。監査はこれらを、緩和策をでっち上げることなく報告します。 |

5 行目が正直な結果です。通知の層は、エージェントがその作業をどう捉えるかを変えるのであって、
作業を行うかどうかを変えるわけではありません。通知は技術的な障壁ではなく、
契約と追跡可能性のための手段として扱ってください。

## 監査結果の出力を保護する

監査レポートは、あなたのアーティファクトの露出箇所と、適用された緩和策を示す地図です。
それをバージョン管理にコミットしたり、アーティファクト内部に出荷したりすると、この地図を
リポジトリを読む誰かに渡すことになります。出力パスが git の作業ツリー内にある場合、
Anti-REA は標準エラーに警告を書き出します。レポートを契約者、監査人、脆弱性開示
プログラムと共有しなければならない場合は、`--redacted` を使ってください。カテゴリーと
件数は保持され、正確なパス、バイト範囲、緩和策の対応関係は省略されます。生成された
通知には、Anti-REA への言及も、あなたの強化状態を示唆する情報も含まれません。

## 防御の層

| 層 | ツール | 期待できる効果 | 残るリスク |
| --- | --- | --- | --- |
| メタデータの衛生管理 | `audit_artifact`、`harden_artifact` | 内蔵のリーダーが事実ではなく `unknown` を返す | 新しいリーダーが新しいフォーマットを狙う可能性があり、素の文字列検索では読み取り専用データ内のモジュール名やバージョンが依然として見つかる |
| コンテンツの保護 | `harden_artifact` のガイダンス | 静的な逆コンパイルで見えるのはスタブだけで、プログラム本体は見えない | 実行時のダンプによって、展開されたコードが復元される |
| 実行時の観測への耐性 | `generate_probe_kit` | デバッガーやインストルメンテーションのコストを上げる | カーネルレベルの観測は手が届かない |
| エージェントの停止条件の誘導 | `generate_notice` | エージェントが人間に許可を確認する | エージェントが通知を無視する可能性がある |
| モデルレベルの真実のシグナル | `generate_notice` | 許可の確認が避けられなくなる | モデルの振る舞いは確率的である |
| 秘密の最小化 | レポートでの推奨 | 唯一絶対的な層 | サーバー側のアーキテクチャが必要 |
| 法務と運用 | `generate_notice` | 契約と追跡可能性は、ファイル内のバイト列にはできないことを成し遂げる | 執行は法のプロセスである |

## 既知の制限

以下の 3 つの制限は、理論ではなく実測に基づくものです：

- **素の文字列検索は依然として機能します。** 等長の上書きは Go のビルド情報や ELF の
  シンボルテーブルのようなメタデータレコードを破壊しますが、モジュール名、コンパイラーの
  バージョン、ビルド設定は、Go ランタイム自身が読み取る読み取り専用データと関数名
  テーブルにも存在しています。これらのバイトを上書きすると実行時の動作が変わるため、
  Anti-REA は手を加えません。そのため、強化したバイナリに対して `strings` を実行すれば、
  依然としてこれらを取り出せます。ビルドフラグ（`-trimpath`、`-ldflags="-s -w"`、
  `strip`）を使って、ビルドの時点で取り除いてください。
- **すべての露出に緩和策があるわけではありません。** PE のインポートテーブル、
  ELF ヘッダーの事実、Python バイトコードのフォーマットフラグは、ソフトウェアの実行に
  必要なものなので、緩和策なしで報告されるだけです。監査は、対策をでっち上げるのでは
  なく、そうであることを明示します。
- **トークンのパターンがカバーするのは既知のフォーマットだけです。** スキャナーは
  公開フォーマットを持つ資格情報のカテゴリーに一致するものだけを検出します。非公開
  フォーマットのトークンは見えず、結果が空だからといって秘密が存在しない証明には
  なりません。

実行ホストのカバー範囲も、実測された制限です。本ツールはネイティブ依存のない純粋な
Node.js で書かれていますが、テストスイートとフィクスチャの実行は Windows だけです。
macOS と Linux でも動く見込みですが、まだ検証されていません。

## FAQ

<details>
<summary><strong>強化するとアプリケーションが動かなくなりますか？</strong></summary>

緩和策は等長の上書きか、すべてのフォーマットチェックをやり直す全体の再配置です。
ユーザーが依存する構造を壊す実行は、`verify` で不合格になります。実行時の動作を変える
ものは、理由を明記してスキップされ、実行は試みられません。すでに強化済みの
アーティファクトに対して `harden` を再実行しても、何も行われず、変更なしと報告されます。

</details>

<details>
<summary><strong>このツールはバイナリをどこかにアップロードしますか？</strong></summary>

いいえ。読み書きはすべて、プロセス内のローカルなファイル操作です。ネットワーク
リクエストも、子プロセスの起動も、テレメトリの送信もありません。

</details>

<details>
<summary><strong>どのエージェントが使えますか？</strong></summary>

ローカルの MCP サーバーを登録できる任意のエージェントです。Claude Code、Cursor、
Codex などが該当します。手動で登録する場合は、「エージェントへの登録」にある
JSON ブロックを使ってください。

</details>

<details>
<summary><strong>監査レポート自体が漏えいの原因になりますか？</strong></summary>

はい。そのため、git の作業ツリー内にレポートを書き出すとツールが警告を出し、
`--redacted` を用意しています。これはカテゴリーと件数を保持し、正確なパス、
バイト範囲、緩和策の対応関係を落とします。

</details>

<details>
<summary><strong>監査で何も見つからなかった場合は、どうなりますか？</strong></summary>

その場合、アーティファクトはリーダーが抽出できるものを何も露出しておらず、
レポートにはその制限とともにそう記されます。ただし、空の結果は安全の証明では
ありません。トークンのパターンがカバーするのは既知の資格情報のフォーマット
だけであり、新しいリーダーは新しいフォーマットを狙えます。

</details>

<details>
<summary><strong>決意の固いリバースエンジニアを止められますか？</strong></summary>

いいえ。本ツールは自動化されたリーダーのコストを上げ、あなたの法的立場のための
証拠を残すだけです。デバッガーを使いこなす人や、カーネルレベルのアクセスを持つ人は、
ファイル内のバイト列では抵抗できない範囲にいます。秘密をクライアントに置かないことが、
唯一絶対的な層です。

</details>

<details>
<summary><strong>通知は本当にエージェントを止めますか？</strong></summary>

必ずしも止まりません。本プロジェクトもそうは主張していません。新規に起動した 4 つの
エージェントによる実測サンプルでは、一つも止まりませんでした。通知を読んだ 2 つの
エージェントはどちらも通知を引用し、分析結果の再配布には許可が必要だと指摘しました。
通知は契約と追跡可能性の手段として扱ってください。

</details>

<details>
<summary><strong>バグを見つけました。どうすればよいですか？</strong></summary>

最新のコミットにいることを確認してから、Node のバージョン、対象の種類、
実行したコマンド、その出力を添えて issue を開いてください。
「コントリビューション」を参照してください。

</details>

## 本ツールが行わないこと

Anti-REA は、設計上以下を行いません：

- **プロンプトインジェクションは行いません。** エージェントへの指示ファイル
  （`AGENT.md`、`CLAUDE.md`、`.cursorrules` など）をアーティファクトに埋め込むことは
  なく、AI エージェント向けの指令を書くこともありません。通知は人間の読者に向けた
  事実の記述であり、データの経路（README、LICENSE、NOTICE、バージョンリソース）を
  通じて伝わります。
- **法的主張の捏造は行いません。** 生成される通知の 1 行 1 行は、実在する条項か、
  確認可能な事実です。誇張された脅しは、誰かが一度確認しただけで崩れます。
- **正当なユーザーを害しません。** 緩和策がソフトウェア自身の動作を弱めることは
  ありません。実行時の保護は、脅威モデルに応じて選ぶオプトインであり、
  デフォルトではありません。

## このリポジトリについて

Anti-REA は、設計としてオープンソースです。監査のルールは公開され、秘密は持たず、
攻撃のペイロードも含みません。このツールの価値は自動化と証拠であり、秘匿性では
ありません。唯一絶対的な防御層である、秘密をクライアントに置かないという原則は、
誰がこのコードを読んでも揺るぎません。リポジトリに入れてはいけないものは、
特定ユーザー向けの監査出力だけです。ツールがそれについて警告し、`--redacted` を
用意しているのは、そのためです。

## 検証

すべての機能は、実際のフィクスチャファイルを使う `node --test` でカバーされており、
MCP のインターフェースは標準的な stdio ハンドシェイクによってスモークテスト
されています：

```bash
node --test
node scripts/mcp-smoke.mjs
node tests/fixtures/build.mjs --check
```

現在のスイートは 526 個のテストで、すべて成功しています。あわせて、フィクスチャの
ダイジェスト登録のチェックも行われます。スイートは Windows 上の Node.js 22 と 24 で
実行されています。macOS と Linux のホストでは、まだ実行されていません。

テストスイートが強制する規約については、[CONTRIBUTING.md](../../CONTRIBUTING.md) を
参照してください。

## セキュリティ

Anti-REA 自体の脆弱性は、公開の issue ではなく [SECURITY.md](../../SECURITY.md) の
手順に従って報告してください。「既知の制限」に記された設計上の限界は、
脆弱性ではありません。
